# 判断链与生成链分离：换模型不再让「理解」跑偏

> 创建：2026-09-13
> 定位：解决「换模型后同一句话判出完全不同的结果」——**分类器本质是让 LLM 画一条分界线，换模型就是换把尺子**
> 前序：`agent-json-mode-fix-design.md`（同一天暴露的另一个模型问题：长 JSON 漏收尾括号）

## 一、现象（实测）

同一句话「帮我分析我的Agent学习计划，看看有没有问题」，**一字不差**，三次判出三种结果：

| 时间 | 分类结果 | 后果 |
|---|---|---|
| 22:04 | `GENERAL_CHAT` | 压根没认出来是学习计划 |
| 22:08 | `LEARNING_PROGRESS` | **直接起调整工作流**，问用户"要调整哪个计划" |
| 22:15 | `LEARNING_AGENT` ✓ | 正确 |

中间 PID 变过（58496 → 58844 → 61032）= 重启过 = **换过模型**（百炼免费额度到期就换）。

## 二、为什么会这样

**分类器本质是让 LLM 画一条分界线**。项目 2026-09-12 已经实测过这个性质：
**同一个模型、同一句 prompt、同一句话，30 次跑出 `Agent 20 : QA 10` 的稳定分布**
（见 `agent-v4-intent-boundary-closeout-design.md`）——**连不换模型都在摇摆**，
换模型只是把这条分界线整体推移。

所以「我把后端代码写好、提示词准备好，模型就不会跑偏」这个假设——
**在生成类任务上大致成立，在判断类任务上不成立**。

**关键认识：两条链对稳定性的要求完全不同**

| 链 | 环节 | 判错的代价 | 该用什么模型 |
|---|---|---|---|
| **判断链** | 分类器 / Agent 决策器 / 证据验证器 | **整条路走偏**（要分析却让你改计划） | **绑一个稳的** |
| **生成链** | 大纲 / 草稿 / 计划内容 / 优化方案 | 内容平庸一点，用户能接受 | **随便换，省钱** |

**成本账**：判断链每次只吃一句话（prompt 短）、输出几十个 token——**用强模型的成本远低于生成**。
这是性价比最高的稳定性投资。

## 三、方案

新增一个配置项 `blog.ai.judge-model`（环境变量 `AI_JUDGE_MODEL`）：

- **留空** → 跟随 `spring.ai.openai.chat.options.model`，**行为与改动前完全一致**（有测试锁）
- **配了** → 判断链三个环节用这个模型，生成链不受影响

**接入的三处**（都是决定"下一步走哪条路"的环节）：

| # | 位置 | 作用 |
|---|---|---|
| 1 | `AiIntentClassifierImpl.callClassifier` | 分类器——决定走 Agent / Workflow / 普通聊天 |
| 2 | `LlmAgentStepDecider.callDecide` | Agent 决策器——决定下一步动作（**三域共用基类**，`Article`/`General` 子类自动覆盖） |
| 3 | `ArticleEvidenceVerifier.callVerify` | 证据收敛门——判"证据够不够" |

**刻意没接的**（判错不影响本轮路由）：

- `LlmAgentStepDecider.summarize`（收尾总结，生成型）
- 记忆提取 / 记忆更新决策、对话摘要——它们也是判断型，但判错只影响记忆库质量，不影响这一轮走哪条路

## 四、怎么用

```bash
# 启动环境变量
AI_CHAT_MODEL=qwen3.6-flash              # 生成链：随免费额度换，省钱
AI_JUDGE_MODEL=qwen3.6-plus-2026-04-02   # 判断链：绑一个稳的
```

配了 judge-model 时启动日志会打一行确认（便于核实生效）：

```text
判断链模型已配置: judgeModel=qwen3.6-plus-2026-04-02（分类器 / Agent 决策器 / 证据验证器）
```

## 五、验证

| 项 | 结果 |
|---|---|
| 编译 | ✓ |
| 判断链相关测试 | **94/94 绿**：决策器 4 类 21 例 · 验证器 13 例 · planner 50 例 · 分类选择 6 例 · **新增配置类 4 例** |
| 默认路径零变化 | ✓ 由 `AiJudgeModelSupportTests.blankConfigLeavesBuilderUntouched` 锁定 |

## 六、边界

- **默认零变化**：不配 `judge-model` 等于没有这个类——不是"改行为"，是"多一个开关"
- **不是万能药**：judge-model 自己也会判错（分界线的固有概率），只是"稳的模型稳一些"。
  **换 judge-model 仍建议跑评测门**：`./mvnw test -Dgroups=eval -DrunRealLlm=true`
- **未覆盖**：记忆提取 / 记忆更新决策 / 对话摘要——待观察，确有需要再接
