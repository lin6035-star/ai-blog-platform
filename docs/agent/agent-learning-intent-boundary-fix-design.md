# 学习域意图边界修复：「分析计划」不是「查计划」

> 创建：2026-09-14
> 定位：修「帮我分析我的X学习计划」被判成 `LEARNING_PLAN_QUERY`（查列表）导致不写锚、下一句反问
> 前序：`agent-session-plan-anchor-design.md`（会话学习计划锚）、`agent-v4-intent-boundary-closeout-design.md`（文章域同类边界修复）

## 一、现象

同一个会话，连着三句：

| 时间 | 用户 | 判成 | 后果 |
|---|---|---|---|
| 22:46 | 帮我分析我的Agent学习计划，看看有没有问题 | **`LEARNING_PLAN_QUERY`** | 走 TOOL 查列表，**没有思考过程** |
| 22:48 | 我只是专门让你看Agent的学习计划，不是看整体的 | `LEARNING_PLAN_QUERY` | 同上 |
| 22:49 | 可以，那就按照你的建议修正一下我的计划 | `LEARNING_PROGRESS` ✓ | 意图对了，**但会话锚是 NULL** → 定位不到 → 反问"是哪个计划" |

**而在学习计划详情页问同一句话就是正常的**——页面上下文帮模型判对了，锚也写上了。

**关键**：22:46 和 22:51 是同一个进程、同一个模型，**差异只在页面上下文**。
所以这不是模型问题，是**分类器对「分析计划」这个意图压根没有定义**。

## 二、根因

分类器提示词里：

- `LEARNING_PLAN_QUERY` 的定义是「用户**询问或查看**自己已有的学习计划、阶段或进度」，
  例子是"我有几个学习规划""我的 MySQL 学习计划学到哪了"
- `LEARNING_AGENT` 的定义里只有「继续学什么 / 勾选任务 / 任务改名」三类，
  **唯独没有「分析、评价计划内容」**

于是「**我的**Agent**学习计划**」字面命中"查看自己已有的学习计划"，
而"看看有没有问题"这个真正的诉求没有对应的判据去接——**摇摆**。

**与 2026-09-12 文章域那次同源**：当时是 `ARTICLE_DETAIL_QA` 缺「评价 / 比较」的定义，
补定义 + 正向判据后收敛。**同一个病，换了个位置**。

## 三、修复（改 5 处 prompt）

| # | 位置 | 改动 |
|---|---|---|
| 1 | `LEARNING_AGENT` | **新增一类**：「要求分析、评价已有学习计划的内容（只是要分析结论或建议，**不要求动手改**）」 |
| 2 | `LEARNING_AGENT` | 加**三条分界**：查状态→PLAN_QUERY / 问好不好→本类 / **要求动手改→PROGRESS** |
| 3 | `LEARNING_PLAN_QUERY` | 补边界：只处理「列表与状态查询」，对内容做分析评价不是本类 |
| 4 | 边界例子区 | 补「帮我分析我的 Agent 学习计划，看看有没有问题」→ LEARNING_AGENT |
| 5 | `LEARNING_PROGRESS` | 加**优先声明**：只要用户是要你**动手改**，哪怕带"建议/分析"字样也归本类 |

## 四、自我修正：第一版改宽了（重要）

第一版只在 `LEARNING_AGENT` 加了「分析、评价」一类，例子写成
「这个计划写得怎么样、**怎么改进**」——结果实测：

```text
「可以，那就按照你的建议优化一下我的计划」
→ intent=LEARNING_AGENT, risk=MEDIUM,
   reason=用户要求分析并改进已有学习计划内容，属于Agent受控写提案场景
```

**「优化」被"改进"这个词吸到了 AGENT**——本该走 `LEARNING_PROGRESS`（要执行），
却走成 Agent 分析（而且 Agent 路径不读锚，照样定位不到）。

**处置**（上表第 1、5 两处）：
- 分析段的措辞收窄为「**只是要分析结论或建议、不要求动手改**」
- 补一条判据：「"改"出现在"**要你改**"里就是 PROGRESS，只有"**问你该怎么改**"才是本类」
- 在 PROGRESS 区加优先声明，从**两边同时**把这条线画清楚

**教训**：补边界时，**新规则要在两侧都写**——只在一侧加"归属"，会把另一侧的样本吸过来。

## 六、顺带发现：Agent 路径不读会话锚

第二句一度被判成 `LEARNING_AGENT` 时，Agent 的回答是：

> 我看到你有多个进行中的学习计划，请问你希望优化哪一个计划？

**它查了列表，但没用上锚**。查代码确认：**锚的消费点只有两处**——
两个 `routeXxxWorkflow` 的兜底链（`AiMessageServiceImpl:1226` / `1324`），
**Agent Runtime 路径完全不读锚**。

**含义**：只要一句"改计划"的话被判进 AGENT（而非 PROGRESS），
就一定会重新问"哪个计划"，**哪怕上一轮刚聊过**——独立于本次 prompt 问题的另一个缺口。

**登记不做**（本轮），理由：本次 prompt 修好后，"要执行"的话都走 PROGRESS（锚生效）；
剩下的"纯分析 + 没点名计划"场景（如"帮我看看我的计划怎么样"）才会暴露这个缺口，
需要单独一刀（动 Agent 上下文注入 + 补测试）。
