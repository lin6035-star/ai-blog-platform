## 〇、结论先行（2026-09-12 实测后重写）

**实测**（新测试 `AgentRouteBaselineTests`，文章详情页，模型 `qwen3.5-plus-2026-04-20`，分类器原始输出与最终路径分开记录）：

### 第一组 · 原立论那句「对比…」——**不成立（引用失真）**

| 样本 | 句子 | 10 次分布 |
|---|---|---|
| #1 | `对比一下缓存击穿和缓存穿透这两节的写法` | `ARTICLE_DETAIL_QA` × 10 |
| #2 | `对比这两节` | `ARTICLE_DETAIL_QA` × 10 |
| #3 | `对比一下缓存击穿和缓存穿透这两节的写法，说说哪节写得更好，再结合我的写作偏好给建议` | `ARTICLE_AGENT` × 10 |

**30 / 30 零波动**，差异精确对应句子语义（#3 的「结合我的写作偏好」是明确的记忆依赖 + 多目标信号）。**三次记录实际是三个不同的句子**，缩写丢掉了决定性的语义片段 → 详见 §八。

### 第二组 · 待办 2 的「同类不一致」——**成立**

| 样本 | 句子 | 10 次 | 30 次深挖 |
|---|---|---|---|
| #4 | `这篇文章的缓存击穿那一节写得怎么样` | Agent 8 / QA 2 | **Agent 20 / QA 10（2 : 1）** |
| #5 | `整篇文章写得怎么样` | Agent 10 / QA 0 | — |
| #6 | `先看整体结构，再看看缓存击穿那一节` | QA 10 / Agent 0 | — |
| #7 | `先看整体结构，再检查分布式锁那一节` | QA 3 / Agent 7 | **Agent 23 / QA 7（3.3 : 1）** |

**#4 / #7 是真的在切换**，且是**稳定的概率分布**（30 次混合均匀，不是时变故障）。行级 `reason` 显示模型在两种解读之间摆动：

- 判 Agent 时写：「用户对当前文章表述模糊优化诉求」
- 判 QA 时写：「用户询问当前文章特定章节的内容评价，属于文章内容问答」

**同一句话，两种解读都成立** → 这是**分类器的固有边界模糊**，不是实现 bug。

### 处置：**走 A（改 prompt）——已实施 + 已验证（2026-09-12）**

按 §3.1 选择顺序，**#4 / #7 命中第 2 条**（分类器**原始输出**本身就在 QA / Agent 之间切换）→ **优先评估 A**，且「**不要用后端规则掩盖一个没有收敛的分类边界**」。

**根因定位**：`buildSystemPrompt` 里 `ARTICLE_DETAIL_QA` 的定义只列了「讲了什么 / 总结 / 文中概念解释 / 追问文中观点」——**没有「评价、比较」**。而 §1.3 早就指出「比较既像 QA 也像 Agent」，即**设计稿识别的重叠在 prompt 里根本没被消解**。于是「这一节写得怎么样」被模型读成「模糊优化诉求」→ 判 `ARTICLE_AGENT`。

**改动（3 处）**：

1. `ARTICLE_DETAIL_QA` 定义补上「评价或比较」+「某一节写得好不好 / 对比某两节的写法」
2. 加两条正向判据：① 评价 / 比较已有内容（「这一节写得怎么样」「检查一下某一节」）→ **仍判 QA**，明确禁止因「怎么样 / 检查 / 分析」这类词升级为 Agent；② 明确结合记忆 / 写作偏好、或多个连续子目标 → **Agent**
3. 「模糊的优化诉求」条目加注意说明：单纯评价 / 比较不是优化诉求

**验证结果**：见 §十。

**本刀产出**：`AgentRouteBaselineTests`（可复用基线工具）+ prompt 改动 + 上述实测数据。

### 10.3 #6 方向反转的收口（2026-09-13）

**#6「先看整体结构，再看看缓存击穿那一节」从稳定 QA 变为稳定 Agent**。

- **支持改后行为**：观测记录第一轮样本 2 的**预期就是「出 plan（2 项）」**（即 Agent），当时走 QA 被记为待办 2 的问题之一；且 #6 与 #7 现在**行为一致**，而待办 2 的本质正是这两句"措辞几乎相同却判定不同"
- **需要留意**：设计稿 §2.1 判定表要求 Agent 侧是「多步骤 **且** 需要多类信息」，而 #6 的两个子目标**都只读同一篇文章**（单一信息源）——按此标准它更像 QA

**结论**：#6 归入 `ARTICLE_AGENT`。判据不是“用了几个信息源”，而是**用户是否提出了明确的顺序拆解 / 多子目标**。`先看整体结构，再看看某一节` 适合进入 Agent 的 Plan Preview + 分步读文；`某一节写得怎么样` 这种单目标评价仍归 `ARTICLE_DETAIL_QA`。2026-09-13 已补回归样例锁住该边界。

### 10.4 意外发现：分类失败会静默伪装成「模型变笨」

`classify()` 在调用失败时 `return generalChat()`（`AiIntentClassifierImpl:35-38`）——**线上如果 API 出问题，用户看到的不是"服务异常"，而是"AI 对所有问题都不理文章了"**。本轮排查中这个降级路径一度被误读为「新模型能力不行」。

**登记**：这是**有意的容错设计**（单次失败不该让用户完全无法提问），但缺少可观测性——建议后续给降级加计数/告警（`log.warn` 已有，但无人看）。不属本刀范围。

### 原结论先行（讨论稿 v1，前提已被推翻，保留作推理记录）

1. **问题真实且用户可感知**：同一句「对比这两节」四次结果 `Agent / QA / QA / QA`——走 Agent 时有思考过程、走 QA 时没有，用户看到的是「同样的话，有时想有时不想」。
2. **动手前必须先定目标**——观测记录当时留的问题：「**一致性 vs 敏感度**」。当前产品假设是**一致性优先**，但要先用固定基线确认这不是一个本来就稳定的概率边界。
3. **先做基线，再选择 B / A / C**：不能在没有原始分类器输出的情况下直接认定后端裁决优于 prompt 修正。B 仍是低风险候选，但不是预先拍板的实现顺序。
4. **额外提出一个选项 D（统一展示）**——如果痛点的本质是「展示不一致」而非「路由不一致」，那它就是另一个解法。**但它的性质不同（消除感知 ≠ 解决路由），标注清楚由评审决定。**

## 二、目标定义（本刀最重要的部分）

> ⚠️ **前提已消失（2026-09-12）**：本节讨论的「一致性 vs 敏感度」以「存在随机性」为前提。基线实测证明分类器本来就一致，**本节的问题不再成立**。以下内容保留作方法论记录。

观测记录当时留的原话：

> **需要先想清楚目标是什么（一致性 vs 敏感度）**

这两个目标**冲突**：

- **一致性**：这类请求**固定走某一条**（哪怕偶尔选了次优路径，也要稳）
- **敏感度**：允许它**按上下文自己选**（同一句话在不同上下文走不同路径是合理的）

**不先定这个，改 prompt 就是瞎调。**

### 2.1 当前产品假设：**一致性优先**

这是一条产品取舍假设，不是已经由观测数据证明的实现结论。理由是：同一种用户表达如果随机进入不同复杂度的路径，用户难以理解，Agent 路径还会带来额外延迟和模型成本。

**目标判定表**：

| 请求类型 | 目标路径 |
|---|---|
| **单篇文章的内容比较、解释、评价** | `ARTICLE_DETAIL_QA` |
| 明确拆成多步骤，且需要文章 / 记忆 / RAG 多类信息 | `ARTICLE_AGENT` |
| 模糊优化、建议修改、受控写动作 | `ARTICLE_AGENT` |
| 明确要求真正优化文章 | `OPTIMIZE_ARTICLE`（Workflow） |

**「对比这两节」属于第一类** → 目标 QA。

**按这张表看，现状 `1/4 走 Agent` 就是偏差**——目标是把这类请求**压稳到 QA**。

> ⚠️ **反面规则明确排除**：**不得用「出现比较/对比就进 Agent」**——那会把本来一次 QA 能解决的问题升级成 Agent，**方向反了**。
> 同理，**也建议不要用「出现比较就进 QA」的反向硬规则**——过度规则化会把「多步骤比较 + 需要多类信息」的真实 Agent 场景也压掉。

### 2.2 回头看（2026-09-12 补注）

这张目标判定表**本身是对的**——完整句「对比…，说说哪节写得更好，**再结合我的写作偏好**给建议」正是表里第二行「需要文章 / 记忆 / RAG 多类信息」，走 Agent 符合目标。

**出问题的是「把三种句子当成同一句」这个前提**，不是这张表。

## 三、手段对比

> ⚠️ **未启用（2026-09-12）**：B / A / C / D 四个选项**全部不需要实施**。以下设计保留——它们是「如果问题真实存在，该怎么解」的完整推演，其中 §3.2 的判据设计原则（正向证据、不允许用否定证据做肯定判断）与 §3.3 对 D 的性质辨析具有独立价值。

| 选项 | 做法 | 成本 | 风险 |
|---|---|---|---|
| **A · 改分类器 prompt** | 在 prompt 里把 QA / Agent 边界写细、给反例 | 中 | **碰坏其他分界**（不可控）；**必跑 22 例评测门** |
| **B · 后端确定性裁决** | 分类器给结果后，`AgentPlannerSupport` 做一次**窄边界复核** | 低 | 代码级、可单测、可回滚；**不动 prompt → 不触发评测门** |
| **C · 接受概率路径** | 不改，记录边界 | 0 | 用户持续感知 |
| **D · 统一展示** | 不改路由，改为让 QA 路径也展示过程 | 中高 | **性质不同**：消除感知 ≠ 解决路由；且 QA 的"过程"本身内容有限 |

### 3.1 选择顺序：**基线 → B / A / C**（D 单列，见 §3.3）

第一步不是改代码，而是建立可复现的基线。基线之后按以下条件选择：

1. 如果分类器原始输出本身稳定，但最终路径仍有错误，优先考虑 B。
2. 如果分类器原始输出就在 QA / Agent 之间随机切换，优先评估 A；不要用后端规则掩盖一个没有收敛的分类边界。
3. 如果重复测试已经接近稳定，且没有稳定的用户损害证据，接受 C，记录为概率边界，不为追求理论上的 100% 一致性增加规则。

**实测命中第 3 条**（30/30 稳定）——但结案比第 3 条更强：不是「接受概率边界」，而是**输入本来就不同**，分类器没有任何不稳定。

### 3.2 后端裁决的设计原则（若走 B）

- **窄**：只在「**明确该走 QA**」的场景做降级，**不做反向升级**
- **可观测**：每次裁决打日志（`intent=AGENT → 裁决降级为 QA，原因=X`），**便于事后统计裁决命中率**
- **可回滚**：一个开关关掉即回到现状
- **不猜**：判据不足时**保持分类器原判**（宁可漏降级，不可错降级）

**候选判据**（待细化，需用真实样本验证）：

| 判据 | 说明 |
|---|---|
| `pageContext` 在文章详情页 | 只作为文章目标已明确的必要条件，不足以单独降级 |
| 存在明确的文章内容比较 / 解释 / 评价信号 | 这是降级到 QA 的正向证据，不能只因为“没有 Agent 信号”就降级 |
| 不存在优化 / 修改 / 写动作语义 | 这些请求必须留在 Agent 或 Workflow |
| 不存在多来源信息需求 | 若明确要求结合记忆、站内检索或其他外部材料，不能降级 |
| 不存在明确的多步骤结构 | 只能作为排除复杂 Agent 的辅助条件，不能单独决定路径 |

> ⚠️ **这套判据本身也是规则，同样会误判**。特别是“比较 / 评价”不能做成单个关键词命中规则；必须组合正向 QA 证据、目标已明确、无多来源需求和无修改语义。否则 B 会变成另一套不稳定的分类器。

**补注（2026-09-12）**：「不存在多来源信息需求」这条判据如果真上线，**恰好会把完整句（含「结合我的写作偏好」）从 Agent 降级到 QA**——而那是错误降级。这条正好说明「凑规则」这条路的风险。

### 3.3 关于选项 D 的诚实标注

**它的立论**：用户的痛点是「**同样的话，有时有思考过程有时没有**」——落在**感知**上。

**如果** QA 路径也有过程展示（V4 设计稿 §10.1 的「全局思考展示」第二优先项），那**路由不一致就不再可感知**。

**但必须区分清楚**：

- **它解决的是"感知不一致"，不是"路由不一致"**
- **路由不一致本身仍有代价**：Agent 路径多花 token、更慢；而「本来一次 QA 能解决的问题被升级成 Agent」是实打实的浪费
- **且 QA 的"过程"内容有限**（检索 + 生成），做成面板可能收益不高

**所以不建议用 D 替代 A/B，也不建议与本刀并行实施**。QA 的轻量状态展示已经属于 V4.5 的展示主线；本刀应先处理路由本身，避免用展示掩盖错误升级和额外成本。

## 八、方法论：引用失真如何伪造出一个「随机性问题」

这轮的真正教训不在分类器，在**记录方式**：

1. **观测表用缩写记录请求原文**（「对比这两节」）→ 缩写被后续文档（本设计稿 §一）当作原句引用。
2. **缩写丢掉了决定性的语义片段**（「结合我的写作偏好」），而这段恰恰是判 Agent 的正向证据。
3. 于是「同一句走两条路径」在纸面上成立 → 推出「判定不可复现」→ 推出「分类器随机」→ 引出整整一稿关于后端裁决 / prompt 修正 / 展示统一的设计。
4. **实际什么都没有发生**：那是三个不同的句子，各走各的路，都对。

**可迁移的三条规则**：

- **记录请求必须用原文**；缩写要显式标注为缩写。跨文档引用时回原始来源（`ai_agent_runs.goal` / `AgentDecisionTrace` 日志）核对，不要复制二手描述。
- **「判定不可复现」的结论，必须先验证输入是否真的相同**——「同句」的前提是逐字相同，不是「看起来一样」。
- **基线测试（直调 + 重复）比讨论更能定分止争**：本刀从讨论到推翻只用了 30 次分类器调用。

**顺带确认的既有能力**：系统本身已具备核对条件——`AgentDecisionTrace` 日志**同时**记录原始分类输出（intent / confidence / suggestedAction / risk）与最终决策（action / ruleHits / reason）；`ai_agent_runs.goal` 保存真实输入。以后排查路由问题优先看这两处（此前 trace 只输出到控制台、随进程结束丢失的问题**已补**：`logging.file.name: logs/blog-system.log` + 50MB / 7 天 / 1GB 滚动，`.gitignore` 已加 `logs/`）。

### 8.1 本轮调查自身犯的两次错误（记下来，比结论更有用）

| # | 错误 | 代价 |
|---|---|---|
| 1 | **用缩写替代原文**——观测表记「对比这两节」，后续文档把它当原句引用 | 整整一稿设计建立在**不存在的问题**上 |
| 2 | **用小样本推全体**——只测 3 句（且都是对比句的变体）就下结论「分类器没有随机性」，并据此把本稿改成「结案不做」 | 结论被后续 7 句实测打脸，文档二次返工 |

**两次错误同源**：都是**拿手里的有限样本当作全体的代表**。观测者用 1 次样本推出「随机性」，调查者用 3 句样本推出「无随机性」——**方向相反，病根相同**。

**加固规则**：下结论前先问「**我这个样本能覆盖待断言的全集吗？**」不能覆盖时，结论必须限定在样本范围内——「这 3 句稳定」≠「分类器稳定」。
