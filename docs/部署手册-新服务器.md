# 部署手册：新服务器全量部署（2026-10-17）

> 场景：换一台新服务器从零部署（旧机 47.88.86.213 的部署方式作废，本次可重复执行）。
> 方案：Docker Compose 编排 MySQL / Redis / Elasticsearch / 后端 / Nginx。
> 裸机方式见 §10（仓库里已有 `deploy/blog-system.service` + `deploy/nginx.conf`）。
> **HTTPS 由 Cloudflare 免费提供**（域名 `hailin.kdns.fr`，CF 终止 TLS、HTTP 回源到源站），源站不用买/装证书。
> CF 的 SSL 模式用 **Flexible**（源站 80，最省事）或 **Full**（源站也用 HTTPS，配 Cloudflare Origin 证书）。
> ⚠️ **域名备案**：`.fr` 不在工信部可备案后缀列表里，**内地服务器（杭州等）不能用这个域名对外提供网站**（未备案域名访问 80/443 会被阿里云拦截）。
> 要用这个域名，新 ECS 请选**香港/海外地域**（免费试用的地域列表里有香港），海外不需要备案。
> 如果已经开了内地机器：只能先用 `http://<公网IP>/` 访问，不绑域名。

## 0. 组件与拓扑

| 组件 | 镜像/产物 | 端口 | 对外 |
|---|---|---|---|
| MySQL 8.0 | `mysql:8.0` | 3306 | 否（仅 compose 内网） |
| Redis 7 | `redis:7` | 6379 | 否 |
| Elasticsearch 8.13.4 | 官方镜像 + **IK 分词插件** | 9200 | 否 |
| 后端 | `blog-system-*.jar`（Java 17） | 8080 | 仅 `127.0.0.1:8080`（排障用） |
| Nginx | `nginx:stable` | 80 | 是 |

外部依赖（不需要部署）：阿里云百炼（LLM / embedding / rerank）、阿里云 OSS（图片）、QQ SMTP（邮件）、GitHub OAuth。

**必须知道的三个特殊性**：
1. **ES 必须装 IK 分词插件**：站内搜索索引用 `ik_max_word`（`ArticleSearchService`），官方镜像不带，缺了会**建索引失败、搜索静默降级成 LIKE**。见 §4。
2. **RAG 向量索引不会自动初始化**：`article_rag_active` 别名只由「重建」动作创建，新环境首次部署后必须手动触发一次 rebuild。见 §8.3。
3. **MySQL 初始化脚本只在空库首次启动执行**：`init.sql` 非幂等（部分 DDL 没有 IF NOT EXISTS），重复执行会报 Duplicate column。见 §5。

## 1. 服务器准备

建议 4C8G（ES 1G 堆 + MySQL 1G + 后端 1G + 系统余量）；2C4G 可跑但 ES 堆要压到 512m。

```bash
# Ubuntu 22.04 / Debian 12
apt update && apt install -y docker.io docker-compose-plugin curl
systemctl enable --now docker

# 防火墙：只开 22 / 80（未来 443）
ufw allow 22 && ufw allow 80 && ufw enable

# 目录
mkdir -p /opt/blog/{mysql/data,redis/data,es/data,backend/config,frontend,db,nginx}
cd /opt/blog
```

> ⚠️ 不要对外暴露 3306/6379/9200/8080。**8080 尤其重要**：后端只信任 Nginx 覆盖写入的 `X-Real-IP`，直连 8080 时客户端可以自己伪造这个头，绕过全部 IP 限流。

## 5. MySQL 初始化

- `init.sql` 挂在 `docker-entrypoint-initdb.d`，**只会在 `mysql/data` 为空时执行一次**。
- 脚本包含建库、29 张表、**6 个固定分类**种子数据（后端 / 前端 / AI / Agent / 开发工具 / 代码人生 / 阅读）。
- 账号由 compose 的 `MYSQL_USER`/`MYSQL_PASSWORD` 自动创建（`init.sql` 本身不建应用账号）。
- **不要重复执行 `init.sql`**（非幂等）。需要重来就 `docker compose down && rm -rf mysql/data`。
- ⚠️ **字符集**：`init.sql` 是 UTF-8，且脚本开头已有 `SET NAMES utf8mb4;`。命令行手工导入时仍建议显式带参数，否则 Windows 客户端默认 GBK 会把中文种子数据写乱：
  ```bash
  mysql -u myRoot -p --default-character-set=utf8mb4 < db/init.sql
  ```
- **旧库升级（已有 4 类分类的库）**：不要重跑 `init.sql`，执行一次分类迁移脚本：
  ```bash
  mysql -u myRoot -p --default-character-set=utf8mb4 blog_system < db/migrate-categories-2026-10-18.sql
  ```
  映射规则：Java 后端→后端、随笔→代码人生、项目实战的文章并入后端、新增前端/开发工具/阅读。脚本非幂等，执行前先备份。
- 旧服务器数据迁移：`mysqldump --single-transaction -u root -p blog_system > dump.sql` 并用 `--default-character-set=utf8mb4` 导入；导入后**注意 `users.id` 是雪花 ID，保持原值**。
- DDL 变更没有迁移工具（项目约定手工执行），发版前对比 `db/init.sql` 与实际库。

## 6. Nginx 配置（容器版）

`/opt/blog/nginx/blog.conf`——与仓库 `deploy/nginx.conf` 相同，只改两处：`upstream` 用服务名、`server_name` 改成域名。
另外必须把 `deploy/cloudflare-realip.conf` 放到同目录并挂载进容器（见 §3 的 volumes 与 §6.1）：
它负责把 `CF-Connecting-IP` 还原成真实用户 IP，**缺了它游客 AI 每日额度、登录失败 IP 计数会被全站共用**。

```nginx
upstream blog_backend {
    server backend:8080;      # 容器网络用服务名，不是 127.0.0.1
}

server {
    listen 80;
    server_name hailin.kdns.fr;   # 换成你的域名；用 IP 直连也能命中（单 server 场景）

    root /usr/share/nginx/html;
    index index.html;

    client_max_body_size 15m;   # 后端上传 10MB，Nginx 默认 1m 会 413

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 256;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # AI 流式：必须关缓冲 + 长超时，否则 SSE 憋字 / 长任务 504
    location /api/ai/ {
        proxy_pass http://blog_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }

    location /api/ {
        proxy_pass http://blog_backend;
        proxy_set_header Host $host;
        # 真实 IP 只由这行覆盖写入；后端只信任 X-Real-IP
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> 静态资源缓存分层（index.html 不缓存 + hashed assets 强缓存）属于发布流程优化，可后置：在 `location /` 里加 `location ~* \.(js|css|png|svg|woff2)$ { expires 30d; }` 并在 `location = /index.html` 加 `add_header Cache-Control no-store;`。

### 6.1 Cloudflare 接入要点（当前域名 `hailin.kdns.fr`）

1. **DNS**：Cloudflare → DNS → A 记录 `hailin` → 新服务器公网 IP，**代理状态开启（橙色云）**。旧机 IP 先别删，切换后观察 1~2 天再删。
2. **SSL/TLS 模式**（CF 面板 → SSL/TLS → Overview）：
   - **Flexible**（最省事）：CF → 源站走 HTTP 80，源站不需要证书。**源站不能做 80→443 跳转**，否则 CF 回源被 301 到 443 会 525/522 循环。
   - **Full / Full(strict)**：CF → 源站走 HTTPS 443；源站用 CF 免费签发的 **Origin Certificate**（SSL/TLS → Origin Server 生成，15 年），Nginx 加 443 server 块。
3. **Always Use HTTPS** 打开（现在已经是开着的：HTTP 会 301 到 HTTPS）。
4. **真实 IP（必做）**：`conf.d/cloudflare-realip.conf` 随仓库提供，按 §3 挂载进容器。验证：后端日志里的客户端 IP 是用户真实 IP，而不是 `172.64.x.x` / `108.162.x.x` 这类 CF 段地址。
5. **安全组**：80 只放行 Cloudflare 网段（官方列表 https://www.cloudflare.com/ips/），22 只放行你自己 IP；**不要对公网开放 8080 / 3306 / 6379 / 9200**（8080 尤其重要，直连可伪造 IP 绕过限流）。
6. **SSE 与 CF**：免费版能透传长流；若发现流式被攒批，检查是否在 CF 上给 `/api/*` 开了缓存规则（不要开），并确认源站 Nginx 的 `proxy_buffering off` 已生效。
7. **环境变量与 GitHub OAuth**：`APP_FRONTEND_URL=https://hailin.kdns.fr`、`GITHUB_OAUTH_REDIRECT_URI=https://hailin.kdns.fr/api/auth/github/callback`；GitHub OAuth App 后台的回调地址同步改成这个域名，否则回调报 `redirect_uri_mismatch`。
8. **切换顺序**：新机用 IP 验证全部功能 → CF 改 A 记录 → 观察 1~2 天 → 释放旧机（旧机 47.88.86.213，阿里云美国洛杉矶）。

### 7.1 RAG 索引首次初始化（必须做一次）

新环境 `article_rag_active` 别名不存在 → 文章 RAG 检索会报错/降级。初始化步骤：

1. 在页面注册你的管理员账号；
2. 查 user_id：
   ```bash
   docker exec -it blog-mysql mysql -uroot -p -e "select id,username from blog_system.users;"
   ```
3. 在 `.env` 加 `BLOG_AI_RAG_REBUILD_ALLOWED_USER_IDS=<你的 userId>`，执行 `docker compose up -d backend`；
4. 浏览器登录后从 DevTools 复制 `localStorage.blog_token`，然后：
   ```bash
   TOKEN=<粘贴>
   curl -s -X POST -H "Authorization: Bearer $TOKEN" \
     http://127.0.0.1:8080/api/ai/rag/articles/rebuild
   ```
5. 确认 alias（在 compose 网络内）：
   ```bash
   docker exec blog-es curl -s "http://localhost:9200/_alias/article_rag_active"
   ```
   有输出即成功；随后把 `BLOG_AI_RAG_REBUILD_ALLOWED_USER_IDS` 从 `.env` 移除并重启（收敛暴露面）。

> 秒杀预热接口同理需要 `blog.seckill.admin-user-ids`（默认空 = 谁都不能调），要用就临时覆盖后调用。

## 8. 上线后怎么改配置（重点）

先记结论：**当前没有配置热更新**（没有 Spring Cloud Config / Nacos / `@RefreshScope`）。所有配置改动都是「改文件 → 重启后端」，重启会中断进行中的 SSE 流和长 AI 任务（优雅停机还没做）。改之前先备份 `.env` 和 `backend/config/`，回滚就是改回去再重启。

### 8.1 三类配置，改法不同

| 类型 | 位置 | 改法 | 是否需要重新构建 |
|---|---|---|---|
| 环境变量类（模型、开关、限流额度、邮箱、OAuth） | `/opt/blog/.env` | 改完 `docker compose up -d backend` | 否 |
| application.yml 里的任意项（RAG 门限、白名单、线程池等） | `/opt/blog/backend/config/application.yml`（Spring Boot 外部配置，优先级高于 jar 内） | 写 YAML 片段 → 重启 | 否 |
| 代码/依赖/新增配置项 | 源码 | 重新 `package` + 重建镜像/替换 jar | 是 |

**为什么不用改 jar 里的配置**：Spring Boot 会自动加载工作目录下 `config/application.yml`，优先级高于 jar 内同名文件。容器里工作目录是 `/app`，所以挂载到 `/app/config/` 就生效——这就是我们在 compose 里挂 `./backend/config:/app/config:ro` 的原因。

例：把 RAG 相关性门限从 0.75 调到 0.72，不用碰 jar：

```yaml
# /opt/blog/backend/config/application.yml
blog:
  ai:
    rag:
      gate:
        rerank-threshold: 0.72
```

```bash
docker compose restart backend
```

### 8.2 常用配置改法速查

| 想改什么 | 改哪里 | 值 |
|---|---|---|
| 生成模型 | `.env` `AI_CHAT_MODEL` | 如 `qwen3.7-flash-2026-07-15` |
| 判断链模型（分类器/决策器/验证器） | `.env` `AI_JUDGE_MODEL` | 建议稳的模型 |
| 关闭 Jev 快速路径 | `.env` `BLOG_AI_CLASSIFIER_ENGINE=PLUS_ONLY` | 线上判错时回退用 |
| 分类器 prompt 模式 | `.env` `BLOG_AI_CLASSIFIER_MODE=FULL` | `ON_DEMAND`（默认）/`FULL` |
| 关闭/开启思考模式 | `.env` `BLOG_AI_DISABLE_THINKING=false` | 默认 true（关闭思考） |
| 游客 AI 每日额度 | `.env` `AI_GUEST_DAILY_LIMIT` / `AI_GUEST_GLOBAL_DAILY_LIMIT` | 默认 10 / 2000 |
| 全站 AI 每分钟上限 | `.env` `AI_RATE_GLOBAL_PER_MINUTE` | 默认 120 |
| RAG 门限 / rerank 模型 | `backend/config/application.yml` | `blog.ai.rag.gate.rerank-threshold` / `blog.ai.rag.rerank.model` |
| 邮件服务商 | `.env` `MAIL_*` | 换服务商只改这几个 |
| OSS 凭证 | `.env` `OSS_ACCESS_KEY_ID/SECRET` | |

### 8.3 换模型的额外注意事项（容易踩）

1. **换 embedding 模型 = 必须全量重建 RAG 索引**，否则向量维度/语义空间不一致，检索直接废。步骤：改 `.env`/外部配置（`embedding-model` + `dimensions`）→ 重启 → 调一次 `POST /api/ai/rag/articles/rebuild`（同样需要白名单）→ 确认 alias 切换。Memory 向量也要重刷（`/api/ai/rag/memories` 相关接口）。
2. **换 rerank 模型 = 必须重新标定 `gate.rerank-threshold`**（0.75 是按当前 `qwen3-vl-rerank` 的实测分数标定的，换模型后正负例分布会变，不重标定会静默变成过度保守或形同虚设）。
3. **换 chat 模型注意思考参数**：`BLOG_AI_DISABLE_THINKING=true` 会注入 `enable_thinking=false`，个别模型版本不支持会报 `InvalidParameter`。换完看启动日志 `[THINKING]` 和第一次对话；不支持就把该模型加进 `exempt-models` 或关掉全局注入。
4. **换判断链模型后建议跑分类器评测**（`docs/agent/agent-eval-gate.md`，固定 JSON 67 条），否则判错只会表现为「回答怪怪的」，没有报错。
5. 改完一定要在日志确认生效值：`[判断链模型] 解析结果`、`[THINKING]`、`SensitiveConfigStartupValidator` 打印的配置来源。

### 8.4 以后想做热更新（当前不做）

最小改造路径：加 `spring-boot-starter-actuator` + `@RefreshScope` 到配置类，暴露带鉴权的 `POST /actuator/refresh`（只在内网/本机），改外部配置后调一次即可不重启。更重的方案是接 Nacos/Apollo。按项目定位，热更新只对「模型名、开关、阈值」这类有价值，代码/依赖更新本来就要发版，所以不急。

## 11. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即失败，日志说敏感项是开发默认值 | 忘了设 `DB_PASSWORD`/`JWT_SECRET` 等（prod fail-fast） | 按 §3 `.env` 补齐；这是保护不是 bug |
| 搜索搜不到但页面正常 | 没装 IK / 索引建失败走了 LIKE 降级 | 看日志 `[SEARCH-INDEX] 创建索引失败`，装 IK 重启（§4） |
| AI 回答正常但文章问答/推荐没有 | RAG alias 不存在 | 做 §7.1 的 rebuild |
| 图片上传 413 | Nginx 没配 `client_max_body_size` | 加 15m |
| AI 流式转圈后一次性出现 / 长任务 504 | Nginx 没关 `proxy_buffering`、`proxy_read_timeout` 太短 | 用 §6 的 `/api/ai/` location |
| 后端连不上 MySQL/ES | 地址还是 localhost（容器内指自己） | `.env` 设 `DB_URL`/`REDIS_HOST`/`ES_URI`（§3） |
| 时间显示偏 8 小时 | 容器/JVM 时区不是 UTC+8 | compose 已设 `TZ` + `-Duser.timezone=Asia/Shanghai` |
| 登录 429 但没点几次 | 触发了登录失败限流（账号维度 5 次/15 分钟） | 等 15 分钟或换账号；不是故障 |
| 发版后白屏 | `index.html` 被缓存、旧 index 指向已删的 hash JS | 清理 CDN/浏览器缓存，或加 §6 的缓存头 |
