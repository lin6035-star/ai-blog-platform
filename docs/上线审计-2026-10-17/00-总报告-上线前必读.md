# 上线前审计总报告（2026-10-17）

> 范围：后端 `blog-system`（527 个 Java 文件）+ 前端 `blog-frontend`（116 个文件）+ 部署资产（Nginx / systemd / env）。
> 方法：5 个领域并行审计（安全 / 部署运维 / 后端正确性 / AI-Agent / 前端），Lead 做构建、启动、接口与限流绕过的实测复核。
> 细则见同目录 `01-安全.md`、`02-部署运维.md`、`03-后端正确性.md`、`04-AI-Agent.md`、`05-前端.md`。

## 一、结论（先说能不能上）

**底子够硬，但不能按现状直接裸奔上公网。**

- 实测通过：后端 `mvn compile` ✅、dev profile 启动 13.4s ✅、前端 `npm run build` ✅ + 163 个单测全绿 ✅、prod 敏感配置 fail-fast ✅。
- 安全主路径是干净的：29 个 Controller / 134 个映射逐个核对，**没有发现「未登录能读他人私密数据」的越权漏洞**；SQL 注入零命中、无 SSRF、XSS 主路径 4 个 `v-html` 全过 DOMPurify。这比大多数练习项目强。
- **真正的风险集中在两处：① AI 的钱；② 部署资产本身。** 按当前配置上线，最坏情况是「上线第一天 AI 账单被别人刷爆」和「AI 流式/图片上传不可用」。

**最短可上线路径**（想先上线看看，把 P0 里最重的两条绕开）：
1. 先**关掉游客 AI**（后端 `/api/ai/chat/stream` 游客分支直接拒绝 + 前端隐藏游客入口）——这一刀同时消掉 P0-1 和 P0-2 的主要暴露面；
2. 修 Nginx 三项（SSE、上传大小、HTTPS/源站封锁）；
3. 把工作区代码提交并打 tag，产出可回滚的构建产物。

## 二、P0（上线前必须处理，否则上线当天就出事）

### P0-1 游客可免费无限刷 AI，且 IP 限流可被伪造头绕过（账单风险 · 已实测坐实）

- 游客（不登录）可调用 `/api/ai/chat/stream`（`WebMvcConfig.java:42-46`），走 `streamGuestChat` 分支（`AiMessageServiceImpl.java:242-244`），**不计费**；用户 token 用量直接丢弃（`AiMessageServiceImpl.java:3757/3950`），被刷都查不到账。
- 唯一门禁是「游客按 IP 5 次/分钟」（`AiRateLimitInterceptor.java:74-91`），而 IP 取自客户端**可写**的 `CF-Connecting-IP` / `X-Forwarded-For`（`ClientIpUtils.java:12-24`），Nginx 原样透传（`deploy/nginx.conf:31-35`），后端还监听 0.0.0.0（无 `server.address`）。
- **实测**：同一伪造 IP 连发 → 第 4 次起 429；**每次换一个伪造 IP → 全部 200**。另外登录用户去掉 `Authorization` 头就自动降级为游客，**完全绕开计费**。
- 也没有游客日额度、没有全局日预算熔断（`BlogAiProperties.java:203-226`）。
- 后果：上线即等于对外提供一个免费 LLM 网关，脚本可无限调用，阿里云账单不可控。
- 修法：① 修可信 IP 链——Nginx 用 `proxy_set_header X-Real-IP $remote_addr`（覆盖而非追加），后端只信 `X-Real-IP`，或加 trusted-proxy 判断；② 安全组封锁源站直连（只允许 CF 段 / 本机 Nginx）；③ 游客加「每日 N 次」额度 + 全局日预算熔断；④ 最省事：先直接关闭游客 AI。

### P0-2 首跳分类器同步占用 Tomcat 请求线程，AI 无全局并发闸门（整站 DoS 风险）

- `streamChat` 在返回 Flux 之前**同步**跑分类器（`AiMessageServiceImpl.java:220-247/299-301`），plus 路径实测 7.8~12s；AI 长任务准入池（8 worker + 32 队列）**只覆盖 Agent/Workflow，不覆盖聊天**；Tomcat 默认 200 线程。
- 配合 P0-1 的伪造 IP（游客并发不受限），约 200 个并发慢请求就能把 Tomcat 线程占满，整站（包括普通文章浏览）一起卡死。
- 修法：分类器移出请求线程（异步/接入准入池）、对 AI 入口加全局限流（用户级 + 全局）、游客并发单独收紧。

### P0-3 Nginx 完全没配 SSE：AI 流式会「憋字」，长任务 60s 被 504

- `deploy/nginx.conf` 全文没有 `proxy_buffering off` / `proxy_read_timeout` / `proxy_http_version 1.1`，后端也没发 `X-Accel-Buffering: no`。
- 后果：流式回答被缓冲后成批吐出（前端「思考中」卡住然后一次性出现）；Agent/Workflow 长任务超过 Nginx 默认 60s 直接 504。报告里附了可直接抄的 location 配置（`02-部署运维.md` P0-1）。

### P0-4 Nginx 默认 1MB 请求体上限 vs 后端 10MB 上传

- Nginx 未配 `client_max_body_size`（默认 1m），后端按 10MB 放行（`application.yml:89-92`）。
- 后果：手机拍的照片基本都 >1MB，头像/文章插图上传全部 413，且返回 Nginx 的 HTML 错误页（前端提示不可读）。修：`client_max_body_size 15m;`。

### P0-5 部署资产里没有 HTTPS

- `deploy/nginx.conf:9-12` 只有 `listen 80` + 公网 IP，无证书、无 301 跳转、无 HSTS。
- 若前面套 Cloudflare 终止 TLS，则必须同时保证**源站 80/8080 不可直连**（安全组/防火墙），否则密码和 JWT 明文可被中间人截获，且 P0-1 的伪造头会更容易。
- 修：上证书（或确认 CF 全站代理 + 源站封锁 + Authenticated Origin Pull）。

### P0-6 发布基线 = 脏工作区，上线内容不可复现、无法回滚

- 后端工作区 **73 个文件已改未提交**（含验证码、忘记密码、UserSearch 等整套新功能）、前端 15 改 + 5 个未跟踪关键文件（含 `public/static/` 验证码 SDK）；前后端都无 tag、无 CI、无发布脚本；审计前前端 `dist/` 比最后一次源码修改还旧。
- 后果：按 git 发布必丢功能或构建失败；上线出问题没有可回滚的基线。
- 修：提交全部工作区改动 → 打 tag → 用 tag 构建产物 → 记录部署步骤（至少一份 `deploy/README`）。

## 三、P1（强烈建议上线前处理，或上线后 3 天内）

### 钱（AI 计费）
1. **计费漏口 3 处**（文档声称 B1-B4 已补全，实际未闭环）：聊天续跑 `reject` 未计费（`AiMessageServiceImpl.java:2972`）、Agent 建议确认启动 Workflow 未计费（`AgentRunSuggestionService.java:212`，且该路径不在限流清单）、5b handoff 用户触发续跑未计费（`TaskWorkflowContinuationService.java:145`）。
2. **前端 SSE 只从 localStorage 取 token**（`api/ai.ts:735/883`）：不勾「记住我」的登录用户 token 在 sessionStorage → AI 聊天退化为游客（不落库、**不计费**）、Workflow 确认直接 401。这是 P0-1 的「正常用户版」漏口。
3. **`max-tool-rounds` 不是运行时上限**：只参与预扣计算，循环本身没有硬截断；`AiChatDTO` 对消息长度无校验；超出预扣部分平台按预扣封顶（超额成本自己吃）。
4. **取消/断连语义不一致**：聊天取消全额退款，Agent/Workflow 取消后 worker 继续跑完并扣费（`AiMessageServiceImpl.java:1404-1619`），且不释放准入名额。
5. **免费账号可占满长任务池**：注册送 10000 credit，一次 workflow 只扣几十 credit；4 个免费账号 × 每用户 2 并发即可占满 8 worker，其他用户全 503/429。

### 部署与可靠性
6. **生产 ES 地址仍是 `localhost:19200`**（`application.yml:94-95`，prod 无覆盖、无 env 入口）：换一台机器部署，搜索静默降级 LIKE、RAG 全挂，而应用照常启动——最难发现的那种坏。
7. **ES 故障时 ARTICLE_SEARCH 直接抛异常**（`ArticleRagRetrieveService.java:38-94` 无 catch），不是降级；canary 巡检 5 分钟一次，窗口内用户直接报错。
8. **时区未固定**：systemd 无 TZ、JVM 无 `-Duser.timezone`，代码大量 `LocalDateTime.now()`；服务器若是 UTC，全站时间偏 8 小时、每日秒杀 18:00 才开场。
9. **systemd 无优雅停机 / 无 JVM 参数**：每次发版 restart 直接砍断进行中的 SSE 和长 AI 任务；无 `-Xmx`、无 OOM 现场、无 `LimitNOFILE`。
10. **无 MySQL 备份方案**：全仓库无备份脚本，数据丢了不可恢复。上线前至少加每日 `mysqldump` + 恢复演练一次。
11. **`init.sql` 非幂等 + DB 账号写死 `myRoot` + 无增量迁移**：新库照脚本建完连不上（账号不存在）、老库重跑报 Duplicate column 中途退出；`blog.migration.enabled=false`。
12. **前端发布无缓存分层**：`index.html` 与 hash 静态资源同生命周期，半发布/回滚时旧 index 指向已删 JS = 白屏；无回滚方案。
13. **OSS 凭证不 fail-fast**：env 缺失时应用正常启动，上传时才 500。

### 数据正确性
14. **学习计划「调整」路径乐观锁每次静默失败**（已抽查坐实）：`LearningPlanFlowSupport.savePlan` 构造的新实体 `version=0`，`updateById` 在 `@Version` 插件下变成 `WHERE version=0`，DB 里 version 早已 >0 → 影响 0 行且返回值被忽略；但旧阶段照删、新阶段照插 → **计划标题/目标没更新，阶段已替换**，无任何报错。
15. **评论点赞计数是读-改-写**（`LikeCommentsServiceImpl.java:38-49,78-82`）：并发丢更新、取消可减成负数、`updateById` 整行覆盖（文章点赞用的是原子 SQL + GREATEST，对比之下这条明显漏了）。
16. **头像上传 `updateById` 整行回写**（`LoginServiceImpl.java:214-230`）：与改密/重置密码并发时能把旧 `password_hash` / `token_version` 写回去 → 改密被回滚、旧 token 复活。
17. **ES 搜索命中后 DB 回查不带 status**（`ArticlesServiceImpl.java:413`）：索引删除失败窗口内，隐藏文章可能漏出；注释声称的「第二道防线」不成立。
18. **分页参数无上限 + 负数不分页**：公开接口 `page/pageSize` 未 clamp，MyBatis-Plus 3.5.16 对 `size<0` 直接不分页（已反编译确认）→ 未登录即可 `GET /api/articles/hot?pageSize=-1` 触发全表加载（含 LONGTEXT）、`comments?pageSize=-1` 全量评论；评论列表还把 pageSize 拼进 Redis key，可放大内存/Redis。

### 安全
19. **生产安全强依赖 `--spring.profiles.active=prod`**：漏传时用仓库公开的 dev JWT secret 启动且不报错 → 可伪造任意用户 token。修：prod 强制（启动参数校验/环境判定）或 dev secret 改为随机生成。
20. **GitHub OAuth 把 7 天 JWT 放回跳 URL query**（`OAuthController.java:50`）：必进 Nginx/CF access log + 浏览器历史。修：改成一次性 code 换取。
21. 公开接口放大类：`/api/users/{id}/commented` 全量载入内存分页；评论列表 pageSize 进 Redis key（同上第 18 条）。

### 前端体验
22. **HTTP 非 2xx 不解析后端错误体**（`utils/request.ts:122-130`）：登录被限流时用户看到英文 `Request failed with status code 429`，46 处错误展示全受影响（后端中文提示被丢弃）。
23. **首屏主 chunk 3.2MB / gzip 988KB**：31 条路由零懒加载 + naive-ui 全量注册 + 编辑器/highlight 全进主包。改动态 import 即可，预期 gzip <300KB。

## 四、P2 / 工程化欠账（不阻塞上线，上线后一周内排期）

- **文档与实现漂移**（这个项目文档非常认真，所以漂移更要注意）：
  - 文章标签功能**实际未接线**（无 `POST /api/tags`、`article_tags` 无任何业务写入、`Articles` 实体无 tags 字段），但 AGENTS.md 标 `[x]`「文章标签创建/复用」；

  - 材料称三桶限流生效，workflow 桶实际因无 POST 创建端点永不命中（`04-AI-Agent.md` P1-11）。
- **工作区有真实 SMTP 授权码明文**（`blog-system/config/application.yml`，已被 gitignore 但不进 jar）：建议今天去 QQ 邮箱轮换一次授权码。
- 注册送 10000 credit 且无 IP 频控 → 可批量注册薅额度（与 P0-1 同源）。
- 单实例假设未防呆：多实例前必须改 `SeckillSettleTask` 消费者名、AI 准入内存计数上 Redis、启动恢复加实例判据（`03-后端正确性.md` P2-14 有逐任务判定表）。
- 单调度线程会被长任务堵：RAG canary 探针（最长 60s）、`CallerRunsPolicy` 内联重试、5b 巡检同步续跑（可能含 LLM）→ 期间 2s 一轮的秒杀结算停摆。

- `mvn test` 全量约 30 分钟，没有可用于发版的「一次全绿」门禁；前端 vitest 163 例倒是全绿。

## 五、已核实「没有问题」的方向（避免过度补课）

- **越权/IDOR**：AI 会话、Agent run、Workflow、记忆、学习计划、钱包订单、通知、文章隐藏/草稿、AI 读路径全部有 owner 或可见性过滤；未发现未登录读私密数据的接口。
- **注入**：全仓 MyBatis `${}` 零命中；无 SSRF、无路径穿越；CORS 未开放、无 Cookie 会话（CSRF 不适用）。
- **XSS**：前端 4 个 `v-html` 出口全部过 DOMPurify；后端不输出用户 HTML。
- **已验证的既有修复**：验证码二次验证、忘记密码防枚举 + token_version、敏感配置外置、主键/自增、OAuth state、通知越权、token 黑名单——逐条为真。
- **AI 内部**：Agent maxSteps=5 硬上限、流式重试 3 次有界、Memory 不跨用户、QA/工具读文章有可读性校验、写动作确认壳、启动时 AI 依赖不阻塞启动、长任务准入池实现正确。
- **工程实现**：列表不带正文（实测 `content:null`）、延迟双删、缓存一致性、Redis 限流、乐观锁（文章/评论路径）、traceId 贯穿——实现质量在线。

5. **Nginx 三项**：SSE location（`proxy_buffering off; proxy_read_timeout 600s; proxy_http_version 1.1;`）、`client_max_body_size 15m;`、HTTPS（或确认 CF + 源站封锁）。

7. **生产环境变量**：ES 地址（`spring.elasticsearch.uris` + RAG 相关）改成可配置并指向生产；systemd 加 `-Duser.timezone=Asia/Shanghai` 与 `-Xmx`。
8. **修 3 个计费漏口 + 前端 SSE token 读取**（P1-1/P1-2）。
9. **备份**：每日 `mysqldump` + 恢复演练一次；Redis 开启 AOF/RDB。
10. **发版冒烟**：文章列表/详情、登录+验证码、图片上传（>1MB）、AI 流式回答、Agent 长任务（>60s）、手机端首页。
