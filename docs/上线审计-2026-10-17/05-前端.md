## 2. P1 问题

### F-01【P1】SSE 通道只从 `localStorage` 取 token：「不勾记住我」的登录用户 AI 聊天退化为游客、Workflow 确认直接 401

- 位置：
  - `blog-frontend/src/api/ai.ts:735`：`const token = localStorage.getItem('blog_token') ?? ''`（聊天流）
  - `blog-frontend/src/api/ai.ts:743-751`：`fetch('/api/ai/chat/stream', { headers: { Authorization: token ? ... } })`
  - `blog-frontend/src/api/ai.ts:883`、`:887-896`：Workflow approve/reject/retry 流同样只读 `localStorage`
  - 对照：`src/utils/request.ts:62-86`（axios 路径**两个 storage 都读**）、`src/stores/auth.ts:109-121`（不勾记住我 → 只写 `sessionStorage`）
  - 后端：`blog-system/.../config/WebMvcConfig.java:31-44`（`/api/ai/chat/stream` 走可选鉴权）、`:52-70`（`/api/ai/**` 其余接口必须登录）
- 证据链：`setAuth()` 先把 localStorage 里那份删掉、再写 sessionStorage（`auth.ts:113-120`），所以此用户的 `localStorage.getItem('blog_token')` 恒为 `null`；而 `AiAssistant` 用 `authStore.isLoggedIn` 判断 `isGuest`（`AiAssistant.vue:70`）→ 前端认为已登录，把 `sessionId` 传上去（`:2624`），后端却按游客处理（`AiMessageServiceImpl.java:239-244`，`userId == null → streamGuestChat`，游客路径**忽略 sessionId**，返回 `session.id = "guest"`）。
- 用户可见后果（「记住我」默认勾选，取消勾选的用户全部命中）：
  1. AI 聊天**不落库**，刷新/重开面板即丢，历史侧栏里会冒出 `guest` 这条假会话（前端把它当正式会话 `unshift` 进列表，点开触发 `/conversations/guest/messages` 报错）；
  2. **AI 请求按游客计费路径走 = 不计费**（额度白嫖，成本流失；结合后端游客不限次，等于绕过计费）；
  3. 点 Workflow 卡「同意/拒绝/重试」→ 请求无 token → 后端 `JwtInterceptor` 返回 401「未登录，请先登录」（`JwtInterceptor.java:38-41`），功能直接不可用；
  4. 前端仍显示「已登录」，用户完全无法理解为什么 AI 说自己没登录。
- 修复建议：抽出统一的 token 读取函数（把 `request.ts` 的 `readAuthToken()` 导出或放进 `stores/auth`），SSE 两个函数都改用它；**同时补一条 SSE 传输层单测**（断言 `sessionStorage` 场景下请求头带 Bearer），否则同类问题还会复发。

### F-02【P1】HTTP 非 2xx 错误不解析后端响应体 → 用户看到英文 `Request failed with status code 429/402/503`

- 位置：
  - `blog-frontend/src/utils/request.ts:122-130`：响应拦截器 error 分支**只处理 401**，其余直接 `Promise.reject(error)`，没有读 `error.response.data.message`；
  - 展示端普遍是 `error.message`：`LoginView.vue:148-150`、`RegisterView.vue:166-168`、`ForgotPasswordView.vue:47-48`、`SeckillView.vue:125-126`、`WalletView.vue:135-136`、`ArticleDetailView.vue:176-177` 等，全仓共 **46 处** `error.message` 直接进 `message.error`；
  - 后端确实会返回「中文 message + 非 2xx」：`GlobalExceptionHandler.java:27-35`（限流 **429** + Retry-After）、`:41-46`（余额不足 **402**）、`:58-62`（AI 准入 **429/503**）；`LoginAttemptLimiter.java:155` 抛 `RateLimitExceededException(retryAfter, "登录失败次数过多，请稍后再试")`。
- 用户可见后果：
  1. 连续输错密码被锁 15 分钟时，登录页提示是 **“Request failed with status code 429”**——用户无法知道是被限流、要等多久，第一反应是“网站坏了”或去点忘记密码；
  2. 秒杀 `grab` 被 AI 限流（`WebMvcConfig.java:74-82` 包含 `/api/seckill/activities/*/grab`）同样只显示 429 英文；
  3. 任何 5xx 都显示英文状态码，后端准备好的「服务器内部错误」文案被丢弃。
- 修复建议：在 `request.ts` error 分支统一解析 `error.response?.data?.message` 并 `Promise.reject(new Error(msg))`；或提供一个 `toUserMessage(error, fallback)` 工具替换 46 处展示（先改拦截器即可覆盖全部现有调用点）。

### F-03【P1】首屏 JS 3.2MB / gzip 988KB：路由零懒加载 + Naive UI 全量注册 + 编辑器/highlight.js 全量进主包

- 位置：
  - `src/router/index.ts:3-22`：31 个视图全部 `import X from '@/views/X.vue'`（静态），无 `() => import()`；
  - `src/main.ts:3`、`:17`：`import naive from 'naive-ui'` + `app.use(naive)` 全量注册；
  - `src/views/EditorView.vue:6-7`：`md-editor-v3` 及其 CSS 在首屏依赖图内；
  - `src/utils/markdown.ts:2`：`import hljs from 'highlight.js'`（全量语言）；
  - 构建证据见 §1.1（主 chunk 3,140 KB / gzip 987.61 KB，且 `dist` 无页面分块；Nginx 已开 gzip，见 `blog-system/deploy/nginx.conf:18`）。
- 用户可见后果：游客看一篇文章也要先下载并解析含「编辑器 + 钱包 + 秒杀 + 开发面板」的整包。按 4G 有效带宽 8~15 Mbps 估算，仅 JS 就多 2~4 秒；低端机解析 3.2MB 脚本有明显白屏/卡顿，移动端首屏体验明显差。
- 修复建议（收益最大、改动最小）：① 路由全部改动态 import（31 行改动，编辑器/开发面板/钱包页立即移出首屏）；② 长期把 `naive-ui` 改按需引入、highlight.js 改常用语言子集注册；③ 验收标准：主 chunk gzip < 300 KB。

### F-04【P1】发布不可复现：仓库落后工作区 3 天、关键新文件未入库、产物与源码不同步

- 位置/证据：
  - `git -C blog-frontend log -1` → `7b8c7bf 2026-10-14 20:06`；审计时工作区 **15 个修改 + 5 个未跟踪**：`src/views/SearchView.vue`、`src/views/ForgotPasswordView.vue`、`src/views/ResetPasswordView.vue`、`src/components/auth/SliderCaptcha.vue`、`public/static/`（验证码 SDK 产物）；
  - `src/router/index.ts:4-9` 已 import 上述未跟踪页面——**只提交已修改文件而漏掉未跟踪文件的那次提交，会得到一个直接构建失败的仓库**；
  - 审计前 `dist`（13:24:08）早于 `SearchView.vue`（13:37:18），见 §1.3；
  - 无 `.github/`、无 Dockerfile、无前端部署脚本；`dist/` 被 gitignore，只能手工构建+拷贝。
- 用户可见后果：一旦需要热修/回滚，无法从 git 重建「当前线上那份」；按 git 发布旧版本会丢搜索页/忘记密码/登录验证码等最近功能，混合状态则可能构建失败。
- 修复建议：上线前把所有前端改动（含 `public/static/tac/` 验证码 SDK，注意它是**构建必需产物**）提交打 tag；加最小 CI：`npm ci && npm run build` 通过后上传产物，回滚按产物版本而不是按源码目录。

## 3. P2 问题

### F-05【P2】Markdown 编辑器预览没有过 DOMPurify（唯一绕过统一清洗出口的渲染点）

- 位置：`src/views/EditorView.vue:404-410` 的 `<MdEditor>` 未传 `:sanitize`；`node_modules/md-editor-v3/lib/types/index.d.ts:126-135` 显示 `sanitize` 默认是 `(text: string) => text`（恒等）。
- 证据：其余 4 个 `v-html` 出口全部清洗（见 §4），只有 md-editor 预览由库内部 `innerHTML` 渲染、默认不过滤。
- 用户可见后果：当前仅作者预览自己的文章，属**自 XSS**（低危）；但它与 `utils/sanitizeHtml.ts` 注释里「所有 Markdown 渲染都必须经过这里」的约定不符——将来若有任何页面复用 `MdPreview` 渲染他人内容（例如文章详情改用它），立即升级为**存储型 XSS**。
- 修复建议：`<MdEditor ... :sanitize="sanitizeHtml" />`（一行），并在 `articleOutline.ts`/`markdown.ts` 的出口测试里补一条编辑器渲染断言。

### F-06【P2】AI 流式消息每来一个 chunk 都对全文重新 markdown 解析 + DOMPurify，长回答下主线程 O(n²)

- 位置：`src/components/ai/AiAssistant.vue:3360`：`<span v-html="renderMarkdown(msg.content)" />`（模板里的方法调用，每次响应式更新都全量重算）；`src/utils/markdown.ts:24-27` 每次 `marked.parse` + `DOMPurify.sanitize`。
- 用户可见后果：长回答（例如 RAG 总结/文章分析）末尾阶段每个 chunk 都要重新解析整篇文本，移动端会掉帧、滚动卡顿；消息越长越明显。
- 修复建议：已结束的消息用 `computed` 缓存渲染结果（按 message 引用做 memo）；流式中的消息以 80~120ms 节流渲染，或先纯文本追加、流结束再一次性转 HTML。

### F-07【P2】SSE 断线/超时/401 处理不完整：只弹一句提示、无重试、无空闲超时、401 不清登录态

- 位置：`src/api/ai.ts:858-860`（未收到 STOP → `onError(new Error('连接意外中断'))`）、`:743-751`（fetch 无空闲超时/心跳判定）；`AiAssistant.vue:2859-2877`（onError 只 toast + 保留半截内容，无「重试」入口）；SSE 收到 401 时只走 `resolveRejectionMessage`（`:1210-1222`），**不触发全局 `setUnauthorizedHandler`**（`router/index.ts:186-203` 只有 axios 路径会触发）。
- 用户可见后果：网络抖动/服务端卡住时，用户要么长时间看着“思考中”，要么得到一句“连接意外中断”后只能把问题重打一遍；token 过期时 AI 面板继续显示已登录，需等某次普通接口 401 才被踢出去。
- 修复建议：SSE 增加空闲超时（如 60s 无事件 abort 并提示）+ 失败消息下方「重试」按钮；捕获 401 时复用 `setUnauthorizedHandler()`。

### F-08【P2】没有 404 兜底路由：错误 URL 是一张空白页

- 位置：`src/router/index.ts:37-172` 路由表无 `pathMatch` catch-all；`src/App.vue` 只有 `<router-view>`，页面外壳由各 View 自己包 `MainLayout`。
- 用户可见后果：任何错链/旧链接/手输 URL（如 `/article/1`、`/foo`）渲染为空，用户看不出是“页面不存在”还是“网站挂了”，也没有返回入口。
- 修复建议：加 `{ path: '/:pathMatch(.*)*', component: NotFoundView }`（带返回首页按钮）。

### F-09【P2】上传前无类型/大小校验，超限只能等到服务端报错（且提示不可读）

- 位置：`src/views/EditorView.vue:69-86`（封面上传）、`:109-120`（正文图片）、`:380-386`（`accept="image/*"` 的隐藏 input）；`src/views/ProfileView.vue:405-423`（头像）、`:447-456`（`n-upload` 无 `before-upload`/size 校验）；后端上限 `application.yml:89-92`（`max-file-size: 10MB`）。
- 用户可见后果：手机上常见 8~15MB 的原图会**先完整上传**再被服务端拒绝，等待时间长、失败提示只有「封面上传失败/头像上传失败」，用户不知道是尺寸问题；`accept="image/*"` 只是文件选择器提示，任何文件都能被提交。
- 修复建议：上传前 `file.type.startsWith('image/')` + `file.size <= 10MB`（最好再加前端压缩）；失败提示带原因；`n-upload` 用 `:before-upload`。

### F-10【P2】时间显示没有时区契约：完全依赖「服务器 JVM 时区 = 浏览器时区」

- 位置：`src/utils/format.ts:1-25`、`:80-113`：`new Date(value)` 直接解析后端字符串；后端 Jackson 未配置 `time-zone`（`application.yml` 无 jackson 段），VO 字段是 `LocalDateTime`（如 `AiMessageVO.java:17`），序列化后是**不带偏移**的 `2026-10-17T21:49:29`；部署 systemd 也未见 `TZ` / `-Duser.timezone`（`blog-system/deploy/blog-system.service:17,22`）。
- 用户可见后果：若服务器 JVM 跑在 UTC（Linux 默认，未显式设置时常见），全站时间整体偏 8 小时——刚发布的文章/评论显示「8 小时前」；海外用户看到的是按自己时区解释的服务器墙钟时间。
- 修复建议：明确契约——后端带偏移序列化（或部署固定 `TZ=Asia/Shanghai` 且写入 runbook），前端格式化时显式 `timeZone: 'Asia/Shanghai'`；两者选一但要写进部署文档，别靠默认值。

### F-11【P2】登出后 AI 面板状态不重置，共用设备上可能泄露上一个账号的对话

- 位置：`AiAssistant.vue:3164` 只有 `watch(visible)`，**没有 `watch(isLoggedIn)`**；`isGuest` 由 store 计算（`:70`）；游客分支会把当前 `messages` 写入 sessionStorage（`:2828-2832`）。
- 用户可见后果：登出时若 AI 面板正开着，面板继续显示上个账号的问答；此时再发消息会被当成游客，并在 `onStop` 把这份「上一个账号的对话 + 新消息」写入 `blog_ai_guest_messages`，下一位使用者打开面板即可看到。
- 修复建议：`watch(isLoggedIn)` 时清空消息/会话/Workflow 卡并重置 guest 计数；退出登录流程里统一清理 AI 面板内存态。

### F-12【P2】`ai_ref_*` / `ai_wf_logs_expanded_*` 写 localStorage 从不清理，长期会撑爆配额（进而影响登录写入）

- 位置：`AiAssistant.vue:2822-2825`（每条带 references 的 AI 消息写 `ai_ref_<id>`）、`:2147-2151`（读）、`:1640-1643`/`:1902`（写 `ai_wf_logs_expanded_<workflowId>`）；删除消息（`:2917-2934`）、删除会话、登出都没有对应 `removeItem`。
- 用户可见后果：AI 重度用户 localStorage 无限增长；达到配额后 `stores/auth.ts:119` 的 `target.setItem(TOKEN_KEY, token)` 会抛 `QuotaExceededError`，表现为“登录失败/已登录但刷新就掉线”，且很难联想到是 AI 缓存占满了存储。
- 修复建议：删除消息/会话时同步删 key；给 key 加数量上限（LRU 保留最近 N 条）；`setAuth` 写 storage 包 try/catch 并在配额失败时降级（清缓存后重试）。

### F-13【P2】GitHub OAuth 回调把 token 放在 URL query 里

- 位置：`src/views/AuthCallbackView.vue:22-32`（`route.query.token` → 直接写 localStorage）；token 由后端重定向 URL 携带。
- 用户可见后果：30 天有效期的 JWT 出现在浏览器历史、Nginx access log（默认 `$request` 含 query）、以及任何引用该 URL 的日志/截图里，等于把长期凭证扩散到多个弱保护面。
- 修复建议：改为一次性 `code` 换取（OAuth 标准做法）或 HttpOnly Cookie；过渡期至少在前端取到 token 后 `history.replaceState` 去掉 query（只能减少历史泄露，日志仍需后端改）。

### F-14【P2】AI 面板移动端 `min-width: 360px` 未在窄屏媒体查询里重置，< 384px 视口横向溢出

- 位置：`AiAssistant.vue:4414-4420`（`.ai-panel { width:500px; min-width:360px; max-width:calc(100vw - 48px) }`）与 `:6270-6284`（`@media (max-width:480px)` 里只改了 `width`，`min-width` 仍是 360px）。
- 用户可见后果：320~383px 宽的设备（iPhone SE 一代等）上，面板宽度被 `min-width` 抬到 360px，右对齐后左侧超出屏幕约 40px，输入区/发送按钮可能被裁掉。
- 修复建议：媒体查询里补 `min-width: 0`（或 `min-width: min(360px, 100vw - 24px)`）；顺手把窗口 resize 时的拖拽位置 clamp 回视口。

### F-15【P2】工程化：无 ESLint/Prettier、无 lint 脚本、无 Node 版本锁定；SSE 传输层零测试
