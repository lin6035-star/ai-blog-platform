## bug A · 学习计划乐观锁静默失败

- 文件：`blog-system/src/main/java/com/hailin/blogsystem/service/impl/LearningPlansServiceImpl.java:83-95`
- 根因确认：`LearningPlanFlowSupport.savePlan`（`ai/workflow/LearningPlanFlowSupport.java:571-606`）
  构造的是 `new LearningPlans()`（只 setId），version 恒为实体默认 0；DB 里 version 早被
  `refreshPlanStatus` 推高。`updateById` 生成 `WHERE version=0` → 影响 0 行且返回值被忽略，
  但旧 stages 照删、新 stages 照插 → 计划标题/目标/状态静默不更新。
- 修法：existing 分支先 `plan.setVersion(existing.getVersion())` 对齐库里版本，再
  `if (!updateById(plan)) throw new IllegalArgumentException("计划正在被修改，请稍后重试")`
  （与本类 stages CAS 失败同风格，不引入新异常类型）。
- 测试：`src/test/java/com/hailin/blogsystem/LearningPlanOptimisticLockTests.java`
  ——库里 version=5 + 调用方 version=0，断言标题/目标真的落库、version 变 6、stages 被覆盖重建。修复前必红。

## bug B · 评论点赞计数读-改-写

- 文件：`service/impl/LikeCommentsServiceImpl.java:39-49`（点赞）、`:84-91`（取消）
- 修法：对照文章点赞（`ArticleLikesServiceImpl:97-100/187-190`）改原子 SQL：
  `setSql("like_count = like_count + 1")`，取消 `setSql("like_count = GREATEST(like_count - 1, 0)")`；
  自增后校验影响行数（`!= 1` 抛 `IllegalStateException`），取消不校验（与文章取消一致）。
  取消路径顺手删掉不再需要的 `selectById`。
- 测试：`CommentLikeCountAtomicTests`（点赞/取消同步、双用户累加、计数为 0 时取消不得为负）。
  旧实现「读 0 → -1 → 整行回写」会在最后一条用例写成 -1。H2 支持 `GREATEST`，已实测。
- 附带行为变化：对不存在 / 已软删评论点赞现在抛 `IllegalStateException("评论点赞计数更新失败")`，原先会 NPE。

## bug C · 头像上传整行回写可回滚改密

- 文件：`service/impl/LoginServiceImpl.java:225-237`
- 修法：`updateById(user)`（整行回写）→
  `lambdaUpdate().eq(Users::getId, userId).set(Users::getAvatarUrl, avatarUrl).set(Users::getUpdatedAt, now).update()`；
  只落头像 + 时间戳，上传前读到的旧 `password_hash` / `token_version` 不会再覆盖并发改密/重置写下的新值。
  返回值 VO 逻辑不变（本地 user 已 setAvatarUrl）。
- 测试：`AvatarUploadPartialUpdateTests`（`@MockBean AliyunOSSOperator`，在上传回调里模拟
  「并发改密 + token_version=7」，断言头像已更新且密码哈希/代次未被回滚）。修复前两条断言必红。
